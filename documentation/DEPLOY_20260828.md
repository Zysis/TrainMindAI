  atleta, carico = RPE x durata, tabella esercizi cronometrata ed editabile a mano.
  Nuova sotto-scheda **Presenze** in Analisi.
- **Scala wellness invertita**: su tutte e cinque le voci 5 = condizione migliore.
  Tocca anche la PWA atleti.
- **Atleti**: archiviazione invece di cancellazione, lista in fondo a Squadre,
  posizioni normalizzate sulla sigla, logo squadra.
- **Generatore AI rifatto**: rispetta il numero di settimane richiesto, obiettivi
  sulle zone della curva forza-velocita', nome del mesociclo, squadra, data di
  inizio e giorni di allenamento.
- **Regole di cancellazione**: cancellare un contenitore non distrugge il
  contenuto; tre blocchi 409 al posto delle cascate.
- **Tre lingue vere**: it/en/es allineate a 1883 chiavi, errori API tradotti per
  codice, giorni della settimana da `Intl`.
- Conferme di cancellazione con dialog al posto del `confirm()` del browser.

## 4. Migrazioni dei dati

Tutte e tredici sono **idempotenti**: rilanciarle non fa danni.

```bash
cd /opt/trainmind/trainmind-app/packages/db/prisma/migrations
for f in 2026081*/migration.sql 2026082*/migration.sql; do
  echo "-- $f"
  docker exec -i trainmind-postgres psql -U trainmind -d trainmind_db \
    -v ON_ERROR_STOP=1 < "$f" || echo "!! FALLITA: $f"
done
```

Cose da leggere nell'output:

- **wellness**: `NOTICE: wellness_scale_flip: applicata.`
  Se leggi `gia' applicata, non faccio nulla` era gia' stata lanciata:
  **non insistere**, la conversione e' simmetrica e un secondo giro
  riporterebbe i dati com'erano.
- **cascate**: `no_cascade_on_delete: era CASCADE, convertito in SET NULL.`
  oppure `vincolo gia corretto`. Entrambe vanno bene: la seconda vuol dire che
  lo schema in produzione era gia' allineato.

Controlli:

```bash
docker exec trainmind-postgres psql -U trainmind -d trainmind_db \
  -c 'SELECT name, applied_at FROM "_trainmind_data_migrations";'

# nessun tipo evento vecchio deve sopravvivere
docker exec trainmind-postgres psql -U trainmind -d trainmind_db \
  -c "SELECT type, count(*) FROM calendar_events GROUP BY type ORDER BY 2 DESC;"

# il vincolo deve essere 'n' (SET NULL), non 'c' (CASCADE)
docker exec trainmind-postgres psql -U trainmind -d trainmind_db -c \
  "SELECT conname, confdeltype FROM pg_constraint c JOIN pg_class t ON t.oid=c.conrelid
   WHERE t.relname='training_plans' AND conname LIKE '%periodizationPlanId%';"
```

Nella seconda query non devono comparire `field_training` ne' `training`.

## 5. Ricostruire i container

`--no-cache` e' obbligatorio: dopo un tar, Docker considera spesso il layer
`COPY . .` gia' in cache e ti ritroveresti il codice vecchio.

```bash
cd /opt/trainmind/trainmind-app

dc build --no-cache api
dc up -d --force-recreate api
dc ps                      # attendi trainmind-api "healthy"

dc build --no-cache ai-service
dc up -d --force-recreate ai-service

dc build --no-cache web
dc up -d --force-recreate web

dc build --no-cache athlete
dc up -d --force-recreate athlete

dc ps
```

Due container che sembrano scollegati e invece vanno rifatti:

- **athlete**: la scala wellness vive anche nel form della PWA atleti. Saltarlo
  significa avere i preparatori su una scala e gli atleti sull'altra, **senza
  nessun errore visibile**.
- **ai-service**: prompt e `max_tokens` del generatore sono cambiati. Saltarlo
  significa che "Genera con AI" continua a produrre mesocicli di una settimana.

> Se il build del web esaurisce la memoria (succede sui VPS piccoli):
> `dc stop ai-service`, fai il build, poi `dc up -d ai-service`.

## 6. Verifiche

```bash
curl -s https://api.trainmind-app.com/api/v1/health
dc logs --tail 50 api | grep -i error
dc logs --tail 30 ai-service | grep -i error
docker exec trainmind-api chromium-browser --version   # per il PDF dei report
```

Dal browser su `https://trainmind-app.com/app`:

1. **Calendario** -> crea un *Allenamento Basket* -> **Presenze & Esercizi**.
   Semafori, RPE per giocatore, un esercizio cronometrato, **Completa Sessione**
   senza errori. L'evento diventa **verde**.
2. **Analisi -> Presenze**: i giocatori di quella seduta con % e carico.
3. **Analisi -> ACWR** filtrando su uno di loro: il carico deve comparire **una
   volta sola**. E' il controllo piu' importante di tutto il deploy: se e'
   doppio, il doppio conteggio e' tornato.
4. **Allenamenti -> Genera con AI**: piano di squadra, scegli la squadra,
   **4 settimane**. Devono uscire **4 settimane**, non 1. Salva con "Usa questo
   piano" e controlla che le sessioni cadano sui giorni scelti.
5. **Allenamenti**: il mesociclo appena creato ha il badge **AI generated** e i
   cerchietti dei giorni.
6. **Cancellazioni**: prova a eliminare un mesociclo dentro una periodizzazione
   (deve rifiutare spiegando perche'), poi elimina una periodizzazione e
   verifica che i mesocicli collegati **restino**.
7. **Squadre**: carica un logo, poi la lista atleti in fondo, "Mostra archiviati".
8. **Wellness**: valori bassi rossi, alti verdi. Il periodo predefinito e' 30
   giorni, allarga le date se la tabella sembra vuota.
9. **Lingua**: passa a English e Espanol dalle impostazioni. Controlla i
   cerchietti dei giorni (`M T W T F S S` / `L M X J V S D`), il modale
   "Genera con AI" e un messaggio di errore.
10. **PWA atleti**: un questionario wellness nuovo, poi ricontrolla il punto 8.
